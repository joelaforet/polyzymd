PolyzyMD Conjugation Engine Refactor Plan

Standalone checklist for iterative branches and PRs. This plan preserves the functional conjugation implementation while reducing bloat and duplication in small, validated phases.

Known working checkpoint config:

CONFIG=/home/joelaforet/Shirts-Lab-Linux/Conjugation_Tests/constant_200_conjugation_configs/config_005_linkages.yaml

Branching model:

  • Functional base branch: refactor/conjugation-engine
  • Integration branch for this effort: conjugation-engine-refactor
  • One work branch per checklist phase, branched from conjugation-engine-refactor, e.g. conjugation-engine-refactor-phase-01-shims
  • Each work branch opens a PR into conjugation-engine-refactor
  • When all phases are complete, merge conjugation-engine-refactor back into refactor/conjugation-engine

Global rules

  • Before each phase, inspect git status --short, git diff, and git log --oneline -10.
  • Do not stage pre-existing unrelated changes: pixi.*, POC notebooks/temp files, or untracked local test files.
  • Keep every phase small enough to review independently.
  • Do not touch notebook/marimo POC files unless a dedicated POC cleanup phase is explicitly approved.
  • After each phase, run targeted tests, the conjugation subset, formatting/linting, and the user config checkpoint.
  • Preserve atom order, PDB serials, insertion codes, chain IDs, residue IDs, coordinates, CONECT evidence, and charge provenance.

Standard checkpoint commands

Use the phase number in the checkpoint directory name.

CHECK=/tmp/polyzymd-refactor-checkpoints/phase-N

pixi run -e build polyzymd build --config "$CONFIG" --replicates 1 \
  --scratch-dir "$CHECK/scratch" \
  --projects-dir "$CHECK/projects"

If CLI flags differ, use the equivalent Python workflow call. The checkpoint passes when the known LipA NHS-Lys conjugation build completes and writes the expected conjugation/local-minimization/solvation artifacts.

Phase 8 — Replace custom logic with native APIs where safe

Objective: Use RDKit/OpenFF/Pablo/MDAnalysis/OpenMM native functions where they preserve PolyzyMD identity and provenance requirements.

To-do

  • Replace custom SMARTS/reaction parsing with RDKit reaction APIs where atom mapping is preserved.
  • Use RDKit/OpenFF molecule graph APIs for bond orders/formal charges where synchronized with PDB/SDF atom order.
  • Use MDAnalysis distance utilities for large coordinate/contact calculations if they can operate directly on arrays concisely and faster.
  • Use Pablo native crosslink helpers only where product-state empty-leaving-group behavior is supported.
  • Use OpenMM native state/platform helpers where they simplify code without changing behavior.
