# Analysis plugin contribution checklist

Copy the template below into the pull request body and check the boxes as you
work. Replace `PLUGIN_NAME` with the plugin's lowercase name, and mark an item
`N/A` with a short reason when it does not apply.

The template covers what the observable contract asks of a plugin: where the
module lives, what it imports, what `compute()` returns, how each observable is
described, the two tests, and the commands to run before review. The page that
explains each of those is [Write an analysis plugin](index.md).

## Copy-paste checklist template

````markdown
## Analysis plugin checklist

Plugin: `PLUGIN_NAME`

### Placement and shape

- [ ] The plugin is one module under `src/polyzymd/analyses/`, generated by
  `polyzymd new-analysis PLUGIN_NAME`.
- [ ] The module ends with `PluginAnalysis = contract_analysis(Plugin)`, which is
  what discovery finds.
- [ ] The plugin name is stable, lowercase, and matches how the CLI and
  `comparison.yaml` name it.

### Imports

- [ ] `Observable`, `iter_frames` and `contract_analysis` all come from
  `polyzymd.analyses.contract`.
- [ ] Any other helper comes from `polyzymd.analyses.shared`.
- [ ] Nothing is imported from `polyzymd.analyses._framework`.
- [ ] MDAnalysis, mdtraj and matplotlib are not imported at module scope.

### Settings

- [ ] `Settings` is a pydantic model with defaults and a description on every
  field.
- [ ] An invalid value raises rather than being silently corrected.
- [ ] Selections follow the project convention: `chainid A` for protein,
  `chainid B` for substrate, `chainid C` for polymer.
- [ ] A settings key naming a file the framework does not load is declared
  through `identity_files()`.

### What compute() returns

- [ ] `compute()` returns raw per-frame or per-index values and nothing else. It
  does not average across replicates, run a test, write a file or plot.
- [ ] Every observable states a `unit`, and no unit is still `"TODO"`.
- [ ] Every observable's `kind` matches what its values are.
- [ ] A `profile` states an `index` with one entry per value, and sets
  `n_frames` when it also declares `reduce`.
- [ ] An observable that is a function of others the plugin reports is declared
  `tested=False`.
- [ ] A bulky array a user may want back is returned as an extra sidecar rather
  than as an observable.

### Science

- [ ] The method paper is cited in the module docstring under a NumPy
  `References` heading and repeated in `references`.
- [ ] The replicate is the sampling unit for every reported uncertainty.
- [ ] The `livecoms-check` skill passes.

### Tests

- [ ] One test asserts what `compute()` measures on `synthetic_universe()`,
  including the frame count over the production window.
- [ ] One test runs `run_in_memory` over three replicates and asserts on the
  aggregate fields, not on the raw observable.
- [ ] A test that needs real trajectory data is marked `@pytest.mark.slow`.

### Documentation

- [ ] The plugin has a reference page under `docs/source/reference/` naming
  every settings key, its default and its unit.
- [ ] `comparison.yaml` documentation names any new settings key.
- [ ] The CHANGELOG records the new analysis and its observables.

### Commands before review

```bash
PLUGIN_NAME=my_plugin

PYTHONPATH=$PWD/src pixi run -e test pytest "tests/analyses/plugins/test_${PLUGIN_NAME}.py" -q
PYTHONPATH=$PWD/src pixi run -e test pytest tests/analyses -q
pixi run -e build ruff check src tests
pixi run -e build black --check src tests
pixi run -e build make -C docs clean html
```

A clean Sphinx build must complete with zero warnings before review.
````
